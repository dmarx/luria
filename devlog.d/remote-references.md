**Foreign decisions got a namespace, which turned out to be the thing [ADR-014](decisions/ADR-014.md) was missing rather than the thing it rejected.** [ADR-014](decisions/ADR-014.md) considered exactly this — a prefix for the ancestor project, resolved by a URL template — and rejected it on a fact that is true: strata-g's filenames carry title slugs, so no template can turn `032` into `adr-032-changelog-ci-collection.md`. The reasoning was sound and the conclusion was wrong, because it assumed the only input was a template. The missing input is **discovery**: a slug filename can't be computed but it can be *read*, and once read it can be committed. Worth recording as a pattern — "the obvious mechanism can't produce X" is a much weaker claim than it sounds, because it silently assumes the mechanism has to *derive* X rather than *learn* it once.

`SG-ADR-032` composes a registered prefix with the remote's own code, which matters more than the four characters suggest: a flat `SG-032` throws away which of the remote's schemes the number belongs to, and a remote with both decisions and principles has two number 4s.

**The real work was precedence, not URLs.** A composed code contains a local-looking code, and four separate scanners can each read the tail out of the middle and quietly say something about the wrong project — the reference finder, the fixer, the citation scan, and the annotation validator. Each needed the composed span claimed first, and each failure mode is silent and different: the finder would link `SG-ADR-012` to a local file; the citation scan would count it as a citation of the *local* [ADR-012](decisions/ADR-012.md), keeping a retired local decision looking cited forever; and the annotation validator did fail this way, reporting `unresolved-ok: SG-DP-004` as stale with the message "names DP-004, which does resolve here" — true of this project, irrelevant to the claim. `tests/test_remotes.py` has one test per mouth for exactly this reason.

**Two false confidences found by running it, both the same shape.** Rung 3 — fall back to the code-only filename convention — printed `https://github.com/dmarx/strata-g/blob/main/docs/decisions/DP-004.md` for `SG-DP-004`, a file that has never existed, with no hedge. The fix is a rule worth stating plainly: **discovery, once done, is authoritative.** If a lockfile was read *from* the remote and a code isn't in it, the answer is "no such document", not a guessed filename. A never-refreshed remote still falls back, because "we haven't looked" and "it isn't there" are different claims — which is the same distinction [ADR-014](decisions/ADR-014.md) drew about the fixer's silence, arriving from the other end.

The second was `--check`. Every strata-g link came back `404`, because the repo is private and we are anonymous — so the first run of the reachability report declared fourteen perfectly good links broken. A guard that is wrong most of the time gets suppressed, and then the times it is right go unread; this one would have been wrong on its very first run, for every project citing a private remote. It now probes the *repository* once and reports `unverifiable: repo not public` for its documents, keeping `404` for the case where it means something. Three buckets in the summary — broken, absent-per-lockfile, unverifiable — because collapsing them is how the misleading version happened.

**`--check` is deliberately not part of `luria lint`, and won't be.** A lint that depends on someone else's uptime fails for reasons unrelated to the change under test, and the first flaky failure teaches everyone to ignore the output. Discovery is the only command in the package that opens a socket, it is explicit, and its result is a committed file — so CI, an offline checkout and a laptop with network all resolve a foreign reference identically.

**Fired the guard, per [DP-6](design-principles.md#dp-6).** Appended `See SG-ADR-122 for the CI wrapper.` to `docs/project-memory.md`. `luria lint` reported `docs/project-memory.md:136: SG-ADR-122 is not a link`, and `luria link --fix` wrote `[SG-ADR-122](https://github.com/dmarx/strata-g/blob/main/docs/decisions/adr-122-make-wrapped-ci.md)` — the slugged filename it could only have got from the lockfile. That single round is the whole feature end to end: bare foreign code in, correct upstream URL out, with a private repo and no network involved in the resolution.

One number worth keeping: the lockfile holds all 188 of the ancestor's documents, not just the 14 cited. Pruning it would mean every *new* foreign citation needs a refresh, which needs the private clone; the full map means anyone can cite `SG-ADR-104` and get a correct link with no access to strata-g at all. That is the point of committing it, and it is why the file is big.
