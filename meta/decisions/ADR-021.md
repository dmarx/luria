# ADR-021: Luria's own record lives in meta/, beside the scaffold rather than in it

## Context

This repository is two things at once, and had been serving both from `docs/`.

It is a **package** — the `luria` CLI plus the `template/` scaffold that
`luria init` copies. And it is a **project that runs its own machinery on its
own record**, which is the claim [ADR-009](ADR-009.md) makes and the only reason
any of this is exercised before a consumer hits the bug.

Those two things have different audiences and the same directory. Someone
arriving to evaluate Luria opened `docs/` and found twenty decisions about
Luria's internals, eight principles, and a development log — none of which is
what they will get, and all of which sits between them and the four pages that
are. Measured at the time of this decision: the scaffold `luria init` writes is
16 files and 28.6 KB; the record was ~300 KB. The signal was outnumbered ten to
one by the evidence.

The cost is not only navigational. [Issue #3](https://github.com/dmarx/luria/issues/3)
frames it as deadweight for anyone who vendors the repo, which under
LLM-priced-per-token usage is a real bill. That framing is right about the
symptom and slightly off about the cause: under `pip install luria && luria
init` the deadweight is already zero, because nothing in the record is inside
`template/`. What was actually wrong is that the repo *looked* like its record
was the product.

## Decision

Luria's own project memory moves to **`meta/`**, a sibling of `template/`:

    docs/         what the package documents — doctrine, directives, adopting
    template/     what `luria init` writes into a project
    meta/         Luria's own record: decisions, principles, devlog
    luria/        the tool

`paths.docs` accepts a **list of roots**, and each root's `README.md` indexes
its own directory:

    [luria.paths]
    docs = ["docs", "meta"]

Per root rather than repo-wide, because one index spanning both would put each
audience's material in the other's way — which is the thing being fixed. Both
roots are scanned for bare references, so nothing loses a guard by moving.

Two smaller consequences of the same rule:

- **A scheme's directory is scanned on its own account**, rather than by
  happening to be a descendant of a documentation root. It was only ever
  covered because `docs/decisions/` sat under `docs/`; `meta/decisions/` would
  have silently dropped out of the reference lint.
- **A journal's source directory is exempt from the index check**, like a
  scheme's. `meta/devlog.d/` holds entries, not pages to browse, and its books
  already carry an index.

**`CHANGELOG.md` and `changelog.d/` stay at the repository root.** The
asymmetry with the devlog is deliberate and is the point of the split: a
changelog is a claim about the *package*, which an adopter reads, and a root
`CHANGELOG.md` is a universal convention. The devlog is how the package came to
be, which only a contributor reads. Sorting by audience puts them in different
places even though they look like siblings.

**The scaffold is unchanged, and gets no `meta/`.** A project adopting Luria
has one audience and one record; the split solves a problem specific to a repo
that is both a tool and a demonstration of the tool. `template/luria.toml`
keeps the plain `docs = "docs"` string form, which the list form is a
superset of.

## Alternatives considered

- **A separate repository for the meta-memory, submoduled here.** The idea in
  [issue #3](https://github.com/dmarx/luria/issues/3), and it costs the property
  that makes the package credible. [ADR-009](ADR-009.md) is a claim that has to
  keep being true, and several tests are *deliberately* corpus-dependent
  against this corpus — move it out and `luria lint` here has nothing real to
  lint, while the dogfooding claim becomes a claim about a submodule. It also
  does not solve the stated problem: recursive clones are standard enough that
  the bytes come along anyway, and it adds a second repo to keep in sync.
  Segregating the record is not the same as exiling it.
- **Invert the layout: hoist `template/` to the repository root.** Considered
  and set aside as a larger diff for the same outcome. Every path in the tool,
  the tests and the workflows would move, and the root would then mix the
  scaffold's files with the package's (`pyproject.toml` beside
  `changelog.d/_template.md`), which is a *new* ambiguity in place of the one
  being removed.
- **Leave it and document the distinction in prose.** A hand-maintained
  separation, which is exactly the drifting projection
  [DP-3](../design-principles.md#dp-3) names — the second person to add a page
  puts it in the wrong root and nothing says so. Two indexed roots make the
  boundary something the lint can hold.
- **Move `docs/` under `meta/` too, leaving only `template/` visible.** Goes
  too far: the doctrine in `docs/project-memory.md` is the most useful thing
  here for a reader deciding whether to adopt, and burying it optimises for the
  contributor over the visitor.

## Consequences

- **Every link inside the record survived the move untouched.** An ADR's
  `../design-principles.md#dp-3` still resolves, because the whole record moved
  together and the relative shape is unchanged. Only links *crossing* the
  boundary needed rewriting — 94 of them, mechanically, plus one from
  `README.stub` back out to the doctrine.
- **`Config.docs` is now `doc_roots[0]`.** Callers that meant "the" docs
  directory still work; callers that meant *every* root say `doc_roots`.
- **`luria init` is unaffected** — it copies `template/` and never saw `meta/`.
  The deadweight complaint in [issue #3](https://github.com/dmarx/luria/issues/3)
  is answered for the `init` path; it is answered for the *vendoring* path only
  in the sense that what to delete is now one obvious directory.
- **A visitor's first look is now representative.** `docs/` is four pages,
  `template/` is what they get, `meta/` is labelled as evidence and says so in
  its own README.
- Still open from [issue #3](https://github.com/dmarx/luria/issues/3): the
  distribution mechanism itself (PyPI, a release tarball of `template/`, or
  both), and the bare local codes in `template/` that will resolve to an
  adopting project's own decisions rather than to Luria's. Neither is blocked
  by this decision.
