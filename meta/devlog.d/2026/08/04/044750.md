---
title: "Luria's own record moves to meta/, and two hardcoded paths surfaced on the way"
created: '2026-08-04T04:47:50'
tags: []
---

**The repo was serving two audiences out of one directory, and the numbers made
the case better than the argument did.** [#3](https://github.com/dmarx/luria/issues/3)
framed it as deadweight for anyone vendoring the repo. Measuring first changed
what the fix should be: `luria init` writes 16 files and 28.6 KB, while the
record was ~300 KB across decisions, principles, devlog and changelog. So under
`pip install && luria init` the deadweight is *already zero* — nothing in the
record is inside `template/`. What was actually wrong is that a visitor opening
`docs/` met twenty decisions about Luria's internals before reaching the four
pages that are the product. A navigation problem wearing a token-cost costume.
The record moves to `meta/`; `docs/` becomes what the package documents
([ADR-021](../decisions/ADR-021.md)).

**Every link inside the record survived untouched, which is worth knowing before
attempting a move like this.** An ADR's `../design-principles.md#dp-3` still
resolves, because the whole record moved together and the relative shape is
unchanged — `docs/decisions → docs/` and `meta/decisions → meta/` are the same
two hops. Only links *crossing* the boundary needed rewriting: 94 of them, plus
one from `README.stub` pointing back out at the doctrine. The journal entries
were the nicest case: `link_base` resolves them from the journal's configured
*output* directory, so changing `output` in `luria.toml` moved every one of
their link bases at once and not a single entry needed editing. The test that
covers it now reads the journal from config rather than naming a path, so it
asserts the property instead of the current location.

**Two hardcoded paths were flushed out, and both had been wrong-shaped before
they were wrong.** `badges.region()` defaulted its link to the literal
`"docs/decisions/README.md"` — a default restating a configured value, which is
a projection, and projections drift. After the move both README badges pointed
at nothing. It reads `current().index` now. The second was structural: the
reference lint reached the decisions only because `docs/decisions/` happened to
sit under `cfg.docs`, so a scheme directory anywhere else was never scanned.
That one would have failed *open* — `meta/decisions/` dropping out of the
hyperlink lint with no error, exactly the fail-stale polarity
[DP-3](../design-principles.md#dp-3) rules out. `doc_files()` now scans scheme
directories on their own account.

**`paths.docs` takes a list, and the index check runs per root rather than
repo-wide.** One index spanning both roots would have put each audience's
material in the other's way, which is the thing the split exists to fix. The
journal's *source* directory also had to join the exemption list:
`meta/devlog.d/` holds entries, not pages to browse, and it only became visible
to that check by moving inside a documentation root — a rule that had been
correct for two days purely because the directory was somewhere else.

**Rejected: a separate repo, submoduled.** It was the leading idea in the issue
and it costs the property that makes the package credible.
[ADR-009](../decisions/ADR-009.md) is a claim that has to keep being true, and
several tests are deliberately corpus-dependent against *this* corpus — move it
out and `luria lint` here has nothing real to lint. It also doesn't solve the
stated problem, since `--recursive` clones pull the submodule anyway.
Segregating a record is not the same as exiling it, and the version that keeps
the dogfooding is a directory rename.

**Also rejected: inverting the layout to hoist `template/` to the root.** That
was the issue's opening instinct, and the second thought in the same message was
the better one — same outcome, far smaller diff, and it avoids mixing the
scaffold's files with the package's at the top level.

Both new guards were fired before being trusted
([DP-6](../design-principles.md#dp-6)): an unindexed page dropped into `meta/`,
and a bare reference added to a document under `meta/decisions/`. Each produced
exactly one violation. The whole record was then re-resolved — 600 relative
links, one "broken", which is the `ADR-NNN.md` placeholder in the decision
template — and a fresh scaffold was run end to end into an empty directory to
confirm `luria init` still produces a project with no `meta/` in it, because an
adopting project has one audience and does not need this split.
