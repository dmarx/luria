### Added

- A SQLite backend for the record's sources: `backend: {kind: sqlite,
  file: record.sqlite}` in `luria.yaml`, and every command reads and writes
  the database — `luria new` files a row, the lint validates its fields,
  `luria index` renders the views from it. `luria export` converts either
  way: its database now carries a `sources` table beside the derived ones,
  refreshes the derived tables in place under the SQLite backend, and
  `--markdown` writes every source back out as a file ([ADR-tmpk52vs](record/decisions.d/ADR-tmpk52vs.md),
  [#110](https://github.com/dmarx/luria/issues/110)).
- The lint reports a SQLite backend whose database is missing, and a row
  under no source directory.

### Changed

- Every read and write of a source goes through `luria/store.py`, and a
  test holds that no other module opens a path for itself. `luria site`
  skips `build/`, where luria's own commands write.
