### Added

- Named relations on citations ([#333](https://github.com/dmarx/luria/issues/333)): `[[extends::X]]`, or a link titled with the field name, `[X](X.md "extends")`, states that this document holds `X` in its `extends` field. Any reference works, declared or built in. A named relation missing from frontmatter is the new `unrecorded-relations` warning, and `luria link --fix` writes it. The fixer expands the wikilink into the titled link, so the relation shows on hover rather than in the text.
- `explain: true` on a reference field asks for each code the field holds to be cited in the body with the relation named. `unannotated-relations` (the fixer names the relation on an existing plain citation) and `unexplained-relations` (a report, acknowledged per code with the new `unexplained-ok:` directive) cover the two ways that can fail.
- `bad-annotations` reports a named relation the record cannot hold: undeclared, into the wrong scheme, naming no local document, or contradicting a single-valued field.

### Fixed

- A markdown link with a title (`[X](path "title")`) was invisible to the link-target check, the remote hand-link check, view-citation retargeting and the site's frontmatter link rewriting. All four now read it.

### Documentation

- The relations how-to gains a section on stating a relation where you explain it.
