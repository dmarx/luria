# ADR-030: The CLI surface is the workflows, not the module layout

## Context

The CLI had eleven commands because the dispatcher mapped one command per
module: every module keeps a standalone `main()` (so a project can vendor one
file), and registering each in `cli.py` was free. The surface therefore
mirrored the package layout, and it kept growing with it — which is a
projection of an internal structure onto an interface, the drift shape
DP-3 names.

The evidence that the tail was dead was already written down, in three places:

- `reports.py` says in its own docstring that the detail "only existed behind
  `ref-status` and `pending`, **which nobody runs**" — the reason the markdown
  reports exist at all.
- Bare `luria badges` printed a stderr warning that in normal use
  `luria index` writes the badges — a command whose main output was advice not
  to use it. [ADR-029](ADR-029.md) records the incident that prompted the warning: an
  adopter's workflow ran it to no effect.
- This repository's own CLAUDE.md never told contributors about `badges`,
  `reports` or `collect`. The documented surface and the actual surface had
  already diverged.

Meanwhile two of the survivors are real but not human-facing: `luria collect
--commit` is invoked exactly once, in ci.yml — running it by hand consumes
fragments a reviewer was meant to see on the branch — and `luria reports`
exists to produce the artifact `actions/lint` uploads.

## Decision

**Two tiers, and the help text says which is which.**

1. **Contributor commands** — `lint`, `link`, `index`, `journal`, `remotes`,
   `init`. One per workflow: check, fix, regenerate, file an entry, resolve
   foreign references, adopt.
2. **CI commands** — `reports`, `collect`. Listed under "run by CI, rarely by
   hand", still runnable directly.
3. **Retired** — `badges`, `ref-status`, `pending`. Each was subsumed before
   it was retired: `luria index` writes the badge region and `luria lint`
   checks it ([ADR-029](ADR-029.md)); both status reports print as one-line lint
   warnings ([ADR-007](ADR-007.md)) and land in full detail in the `luria reports`
   artifact.

**A retired name answers with where the job went.** `luria badges` exits 2
with "`luria index` writes the README's badges", not "unknown command" —
DP-1 applied to the interface's own history. The pointers live in a
`RETIRED` table in `cli.py`, beside the commands they replaced.

**The modules keep their `main()`s.** Retiring a command removes a dict entry,
not code: `python -m luria.ref_status --all` remains the interactive escape
hatch, the vendoring story is unchanged, and the modules' tests keep running
against the same entry points.

## Alternatives considered

- **Status quo — keep all eleven.** Costs nothing today, but every command is
  documentation: eleven top-level names claim eleven workflows, and three of
  those claims were false. A surface that lies about what you're supposed to
  run is the same drift the record machinery exists to prevent, on the
  machinery itself.
- **Fold `link` into `lint --fix`.** The familiar linter idiom, and the two
  already share `doc_refs.py` so they cannot disagree. Rejected as a separate
  question: the check/fix split is a deliberate [ADR-005](ADR-005.md) shape, `luria link`
  has a path-scoped mode `lint` has no analogue for, and merging saves one
  name while this decision is about removing false claims, not shortening the
  list for its own sake.
- **Delete the retired modules' `main()`s too.** A cleaner amputation, but it
  breaks the vendor-one-file property for zero surface gain — the CLI no
  longer advertises them either way — and it would have forced the interactive
  detail (`--all`, `--as-of`) to grow back inside `reports` immediately.
- **Silent removal — plain "unknown command" for retired names.** Rejected on
  DP-1: the dispatcher knows exactly what was asked for and where the job
  went, and an explicit request deserves an explicit refusal that names the
  successor.

## Consequences

- `luria --help`, the README's command table, both CLAUDE.mds and the Makefile
  now describe the same six-plus-two surface; the `ref-status` and `pending`
  make targets are gone.
- [ADR-007](ADR-007.md) is corrected in place to v2: its choice (reported, never
  enforced) stands, but its Decision section named the two standalone commands
  as the delivery mechanism, and that part is now this decision's.
- An adopter with `luria badges` or `luria ref-status` in a script gets exit
  code 2 and the successor's name on stderr — a break, but a self-explaining
  one, and [ADR-029](ADR-029.md) already moved every scaffolded workflow onto
  `actions/generate`/`actions/lint`, which never used the retired names.
- The one-command-per-module reflex is gone: the next module added to the
  package starts with no CLI presence, and earns one only when a workflow
  needs it.
