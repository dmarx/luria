Review on the [#32](https://github.com/dmarx/luria/issues/32) arc caught the record contradicting itself: [ADR-007](../../record/decisions.d/ADR-007.md)'s
"warnings, **never** able to fail a build" forbids the last rung of the
ladder the project instruments — prose → convention → mechanism →
**guarantee** ([DP-5](../design-principles.md#dp-5)) — for exactly the findings the machinery is best at
counting ([#40](https://github.com/dmarx/luria/issues/40)). The fix is [ADR-035](../../record/decisions.d/ADR-035.md): warn-by-default survives with
all of [ADR-007](../../record/decisions.d/ADR-007.md)'s reasoning intact, and `[luria.lint] fail_on` promotes named
warning classes to lint failures for the projects that want teeth.

Implementation notes:

- The refactor that made it safe: `report_warnings` used to print each class
  inline with its own scan calls; it now reads one `status_sections()`
  computation and either prints a section or appends it to the violations.
  One computation, two consequences — the warning path and the enforcement
  path cannot disagree about what a class contains, the same
  shared-scanner property [ADR-005](../../record/decisions.d/ADR-005.md) uses for the lint and the fixer.
- **Only unacknowledged rows reach a class**, which fell out for free: the
  sections were already built from the acknowledged-filtered pools. Under
  enforcement, `inactive-ok:` stops being a way to quiet a warning and
  becomes a way to state an exception to a failing rule — a better version
  of the same directive.
- A wrong notch (`fail_on = ["retired-refs"]`) is itself a lint error naming
  the vocabulary; a dial set to a notch that doesn't exist must not silently
  enforce nothing ([DP-1](../design-principles.md#dp-1)).

The supersession chase was the bulk of the work: flipping [ADR-007](../../record/decisions.d/ADR-007.md) to
`Superseded` made 43 citations across 30 files go loud at once — the
[ADR-013](../../record/decisions.d/ADR-013.md) rename experience, an order of magnitude larger. The
classification that made it tractable: **present-tense guidance repoints to
the successor** (docs, module docstrings, test headers — the claim they make
is now [ADR-035](../../record/decisions.d/ADR-035.md)'s), while **historical bodies keep their citation and gain an
acknowledgement** (a decision that cited [ADR-007](../../record/decisions.d/ADR-007.md) while it was in force is
quoting the record, not asserting current doctrine). One self-inflicted trap
worth writing down: the blanket repoint changed "([ADR-007](../../record/decisions.d/ADR-007.md))" to "([ADR-035](../../record/decisions.d/ADR-035.md))"
inside two sentences that still said "never affect the exit code" — a
citation swap can silently falsify the sentence around it, so read the
sentence, not just the code.

Also filed from the same review round: the `luria new <kind>` proposal
(generalizing entry creation beyond the journal), taken as its own issue and
arc rather than a rider on this one.
