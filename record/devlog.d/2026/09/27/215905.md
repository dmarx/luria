---
title: 'Reviewing an imported docs draft by running it'
created: '2026-09-27T21:59:05'
tags: []
---

**An external docs draft read well and did not run.** A 26-page rewrite
(README plus tutorials, concepts, how-to and reference under `docs/`)
arrived as a zip and was imported verbatim, then reviewed. It was
reviewed by execution rather than by reading: every tutorial and how-to
recipe was typed into a fresh `git init` + `luria init` repository exactly
as written. Reading alone would have passed most of it. The prose was
fluent, its 14 citations were all Active and on-point, and the failures
only showed when a command ran:

- `luria new RFC` / `luria new ADR` — kinds are the lowercased prefix.
- A converse declared on one side only, or without `many: true`, is
  refused at config load.
- A reference field is required by default, so every root of a chain
  fails `no 'extends:'` unless it says `required: false`.
- "Declare `superseded_by`" — it is built in ([ADR-071](../../record/decisions.d/ADR-071.md)), and declaring it
  naively made every Active entry fail.
- `index --check` on branches — the opposite of [ADR-068](../../record/decisions.d/ADR-068.md).
- `facet_by` naming an undeclared field crashed `luria index` with a
  traceback; `luria collect` on a fresh `init` crashed on a missing
  `CHANGELOG.md`.

**Structure was the other half.** The draft added `docs/index.md` beside
`docs/README.md`, and a hand-written configuration, CLI and findings
reference next to the generated `configuration.md` and the existing
`cli.md` / `directives.md`, plus a coverage matrix. Every one of those was
a hand-maintained projection ([DP-3](../../record/principles.d/DP-003.md)), and each had drifted from its source
before it merged. They were folded into the existing pages rather than
kept. The new pages were placed on the one map the lint checks, next to
the old pages rather than replacing them: the old pages still hold
content the new set lacks (flags, the directive vocabulary, import traps).
Retiring or merging `concepts.md` / `project-memory.md` into
`docs/concepts/` is left open.

**The `docs` tag had drifted too.** 28 ADRs cited from hand-written pages
did not carry it, most of them cited by the *old* pages, long before this
draft. The tag is a convention nothing checks, so it goes stale the moment
anyone cites a decision. It was brought up to date here. A generated
check, or deriving the tag from the citation scan, would stop the drift
for good.

**A guard that caught this branch twice.** Pushing prose with bare codes
makes the generate action commit `docs: repair sources` onto the branch,
and the next local push is then rejected as non-fast-forward. It happened
twice in a row. The fix is upstream: run `luria link --fix` before every
push, not just before the last one.

**Tool bugs the runs exposed, not fixed here:**

- `luria new --help` errors (`no such field 'help'`), despite "every
  command takes `--help`".
- `luria relate` says `luria repair` writes the converse (relate.py);
  only `luria link --fix` does.
- `luria ack` writes an HTML-comment directive inside YAML frontmatter
  when the citation is a frontmatter field, which is itself a violation.
- A reference snippet with no `dir` raises a raw `KeyError`, and a
  `facet_by` on an undeclared field a raw `ValueError` ([DP-1](../../record/principles.d/DP-001.md)).
- `lint.network: bogus` is accepted silently, and `luria new changelog
  --title` is accepted and ignored.
- A fresh `init` → `lint` is not clean: the scaffolded `CLAUDE.md` links
  `docs/design-principles.md`, which exists only if a principles scheme
  does, and the spent-upgrade notice prints on every new record.
- `tests/test_site.py::test_links_out_of_the_site_go_to_the_repository`
  asserts on the real README's `LICENSE` link, so rewriting the README's
  licence line breaks a site test. The draft's "MIT." did exactly that.
