**The guard was fired on a real record before being trusted.** The
new annotation checks ([#333](https://github.com/dmarx/luria/issues/333)) were run against a scratch copy of
`examples/constitution` with `explain: true` set on
`PRACTICE.references.grounds`. The lint reported 4
`unannotated-relations` and 7 `unexplained-relations`. `luria link --fix`
annotated the 4 and left the 7 alone, as designed. A hand-added
`[[VALUE-3]]{here--grounds-->}` came back as `unrecorded-relations` and was
written into `grounds:`, and a `{here--overrides-->}` on a practice (a
relation only `EXCEPTION` declares) was reported as `bad-annotations`.

**Two things the scratch run showed that the unit tests would not have.**
First, `VALUE` renders as an assembled document, so its citations are links
to an anchor (`docs/values.md#value-1`) with no filename to read a code
from. They resolved only because the code is read from the link *label*
before the target. The label is read first for a second reason too: a
remote link's URL can end in a filename that looks like a local code.
Second, the fixer widens a scalar `grounds: VALUE-002` into a list when it
adds a second code. That is `field_edit.add_to_field`'s existing
behaviour for a `many` field and is correct, but it makes the diff larger
than the one-line change an author might expect.

**A bug the tests caught first.** With two explained relations holding the
same code and one plain citation of it, the fixer's first draft annotated
that one citation twice (`[[LIT-1]]{here--cites-->}{--extended_by-->here}`).
The second annotation attached to nothing and showed up as a
`bad-annotations` finding on the next run. A citation carries one
annotation, so the push-down pass now spends each citation it annotates, and
the second relation is reported as unexplained up front instead of after a
fix.

**Not done: the issue's last example.** It shows the fixer writing
`(see [[REF-123]]{--explains-->here})` into a body that never cited
`REF-123`. The same issue calls the explanation non-deterministic and asks for
a report, so that case is a report (`unexplained-relations`), and the
fixer only annotates citations that already exist. The reasoning is recorded
in [ADR-122](../../record/decisions.d/ADR-122.md).
