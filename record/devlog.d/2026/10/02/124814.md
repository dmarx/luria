---
title: 'A catch-all keyword swallows --help'
created: '2026-10-02T12:48:14'
tags: []
---

**[#328](https://github.com/dmarx/luria/issues/328).** `luria new --help` answered "no such field 'help'". Fire shows a
function's help when it sees `--help` only if the function has no
`**kwargs` to hand it to. `new.run` has one: it accepts a scheme's declared
fields as flags (`--source LIT-134` where SOTA declares `source`). So
`--help` arrived as `declared={'help': True}` and was refused like any
undeclared field. Any other command that grows a catch-all will do the same.

The fix pops `help`/`h` before field parsing, and prints the one thing the
generic Fire help never could: the kinds this record scaffolds and the flags
each takes, read from `luria.yaml` like the dispatch ([ADR-036](../../record/decisions.d/ADR-036.md)). Those are
what a first-time reader gets wrong. The first docs draft wrote
`luria new RFC` four times, when kinds are the lowercased prefix. One
per-kind flag list (`accepted_flags`) now feeds both help and the refusal
message. The refusal had been listing a scheme's declared `status` and
`tags` twice, once as universal flags and once as declared fields.

Not done here: a fragment or journal still accepts flags it ignores
(`luria new changelog --title`, [#330](https://github.com/dmarx/luria/issues/330)). `accepted_flags` is the list a
refusal would read.
