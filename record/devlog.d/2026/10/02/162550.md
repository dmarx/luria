**[#191](https://github.com/dmarx/luria/issues/191) was still open after a month of features.** Before building, I checked whether anything since could express it. `excluded_by` (now on any field since [ADR-098](../../record/decisions.d/ADR-098.md)) compares values within one field. `field_groups` counts present fields, and `status` is always present. Derived fields have no conditionals. The issue's exact case still linted clean on `main`. So `forbidden_when` takes `required_when`'s condition in the opposite sense ([ADR-tmpt3gtr](../../record/decisions.d/ADR-tmpt3gtr.md)). The built-in successor field forbids itself while `status` is the scheme's `active` word.

**One condition, two keys.** `_when` parses the shape for both keys, and `_conditions` yields both to the same load-time check, so a misspelled field or value fails for either. Contradictions are refused at load: required and forbidden, a value in both lists, and forbidden on a field with a `default`. The last is easy to miss. A default is never absent, so the rule would fire on documents that never wrote the field.

**Three existing tests were standing in the forbidden state.** Two contract tests and an annotation test put `superseded_by` on an `Active` fixture, because nothing had ever said that was wrong. They were about remote resolution and the annotation fixer, not status, so their fixtures now retire the document first.

**The annotation fixer refused on its own.** `annotations` already declines a write that would leave a document in breach of its contract. A `ref::superseded_by:` annotation on an `Active` note is now reported as a bad annotation instead of being written. No new code was needed for that, and a test now pins it.

**Fired once on a real case.** In a scratch record from `luria init`, [ADR-001](../../record/decisions.d/ADR-001.md) at `Active` with `superseded_by: [ADR-002]` printed `luria: docs lint clean` on `main`. On this branch it is a violation naming `status: Active` and the ADR. This record and every example lint clean under the rule, so none of them held the contradiction.

**Not mine:** `ADR-122.md:123: ref::extended_by names no reference field` prints on `main` too.
