**[#136](https://github.com/dmarx/luria/issues/136) still reproduced after the YAML move.** A `luria.yaml` with only a `journals:` block inherited the `record/changelog.d` → `CHANGELOG.md` fragment directory, and `record.md` listed it. All seven example records list it too, and five list a `devlog` journal they don't keep. I put a file in `record/changelog.d/` in that scratch record and ran `collect` from `main`: it consumed the file into `CHANGELOG.md` and deleted it.

**The design call went to keeping [ADR-047](../../record/decisions.d/ADR-047.md).** Making every undeclared family empty was the cleaner reading of [#136](https://github.com/dmarx/luria/issues/136). It was rejected because it breaks every adopted record at once, and a devlog in the default family would stop rendering without a word. The fix guards the two harms instead ([ADR-tmpky7q2](../../record/decisions.d/ADR-tmpky7q2.md)): `Config.inherited` records which families were left to the default, `record.md` labels them, and `collect` refuses to delete files in an undeclared directory. An empty inherited directory stays quiet, so a scheduled `luria collect --commit` with nothing to do doesn't start failing.

**One trap:** the configuration reference's prose goes through `str.format` (`config_doc.HEADER`), so a literal `{}` in it, as in `fragments: {}`, has to be written `{{}}`. Without that, `luria index` and `luria link --fix` die with an `IndexError` from a parallel worker.

**Fired once on the real case:** the same scratch record on this branch refuses, keeps the file, and prints the two `fragments:` lines. The examples now carry the label. Declaring the families each example actually uses would remove it; that is left as a follow-up.
