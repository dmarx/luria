The first step of the logic-core migration: `luria/facts.py` reads the
configuration and every document into ground atoms, `luria/logic/` runs
clingo programs over them, and `tools/parity.py` holds every later step to
byte-identical `luria lint` and `luria index` output against the last
release.

**The harness was fired twice before being trusted.** Run against itself,
0.36.0 was byte-identical on all ten records: luria's own, nucleation, the
anthology and the seven examples, about seven minutes in all. That shows
the comparison is deterministic. A one-word sabotage of the chain renderer
then produced three reported differences on the anthology, each with a
unified diff. Two things make it hermetic: `lint.network: never` in each
copy, so arXiv being slow or throttling cannot move the output, and copying
the `.git` with each record, because the converse fixer reads HEAD.

**Three assumptions the tests corrected.** Each is worth knowing before
writing rules against these facts:

- **An unpadded code is not an alias.** `LIT-1` does not resolve to
  `LIT-001`: `codes_of` resolves derived aliases, not numbering. The facts
  report what luria reads, so `ref_value` holds `LIT-1`.
- **`edge/3` is not "edges that land".** `edges.graph` keeps any code of a
  declared scheme, resolved or not. Whether a target exists is `doc/2`'s
  business, and a rule that needs landing must join on it.
- **clingo stops at the first model by default.** The wrapper refuses a
  program with more than one answer set, because a generated view must be a
  function of its sources. With `--models=1` it could never see a second
  answer set, so the guard passed a program with four. It now asks for two.

**Scale.** The anthology is 39,385 facts, extracted in 1.6 seconds: 29,439
`value`, 3,144 `edge`, 3,126 `ref_value`, 1,769 documents.
