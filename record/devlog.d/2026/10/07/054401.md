title: 'Logic core step 3: the converse fixer, and a harness that gives it work'

Step 3 of the logic-core migration moves the converse decisions to
`luria/logic/converse.lp`. Each pair is `(S, F, B, T)`. From the working
tree and from HEAD it derives the two sides of every edge. It then
classifies each edge by what changed: written to both sides, taken from
both, or a clash. A clash is either a directed relation asserted both ways
or a withdrawal on one side against an assertion on the other. The HEAD
baseline is a new fact, `head_value/4`, read by one `git grep` per scheme
instead of one per pair and side. The commit HEAD names joins the facts'
fingerprint, so a commit between two questions in one process is seen.

**[#358](https://github.com/dmarx/luria/issues/358) falls out.** The Python kept a pair's two sides in a dict keyed by
field name, so a symmetric relation crossing schemes collided with itself.
The rules name the sides `now_f` and `now_b`, so there is nothing to collide.
[#358](https://github.com/dmarx/luria/issues/358)'s three regression tests are carried into this branch. They fail
against the old Python and pass against the rules, with none of [#358](https://github.com/dmarx/luria/issues/358)'s
patch applied.

**Parity had to be given something to check.** On a record whose relations
already agree, the fixer has no work, so byte parity on lint, index and
reports says almost nothing about it. The harness now also runs
`luria link` and `luria link --fix`. With `--perturb SEED` it first drops
one paired code from a seeded third of the eligible documents and commits
that, then drops one from another third and leaves it uncommitted. The
first third is untouched one-sided edges, which the fixer completes. The
second is withdrawals, which it propagates. It was fired first with 0.36.0
against itself. On nucleation, 206 documents were perturbed and `luria
link` proposed 67 writes and 54 removals in 111 files, byte-identical
between two runs.
