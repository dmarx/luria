Step 4 moves the cross-scheme checks that `luria.yaml` must pass to
`luria/logic/consistency.lp`. They had been spread over `_checked_converse`,
`_check_invariants`, a loop in `_schemes` and the body of `_chains`. Each
refusal is now one derived atom. `luria/consistency.py` words it and raises
the least, using a key that reproduces the loader's old order: per scheme,
converses before invariants, and per chain the scheme, its facets, each
walked field, then output and invariant. So a config with several mistakes
still reports the same one first.

**Record parity cannot see this step.** A real record's config is valid
and never reaches a refusal. `tools/config_parity.py` therefore breaks one
in seeded ways and compares what each build raised, word for word. On
nucleation and the anthology, 700 mutants (300 mixed and 400 chain-only)
gave 583 refusals, all identical, and every refusal kind is represented.

**The tool was wrong the first time it ran.** `python -c` puts the working
directory on `sys.path`, so the "baseline" imported the checkout instead of
0.36.0, and every mutant "differed" by a missing `clingo` import. It runs
isolated (`-I`) now. After the fix, changing one word in one message was
caught: 13 of 60 chain mutants differed.

**Timing markers.** With `LURIA_TIMINGS=1`, luria prints the facts read, each
solve and the whole command to stderr. The parity harness prints per-step
seconds for both builds. The first use found something. On nucleation, inside
`luria lint`, the facts took 17.9 s of wall-clock time but 2.3 s when timed
alone (documents 1.3 s, HEAD baseline 1.1 s). The likely cause is the
render thread pool contending for the GIL while they are read, not the
reading itself. Each consistency solve takes 2 to 4 ms, and config load is
unchanged within noise.
