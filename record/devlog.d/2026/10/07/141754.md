Step 5 was going to be the reference checks in `contract`. Reading them
first changed the plan. For each value they ask whether the code's prefix
is one the field names and whether the code is among that scheme's
documents. Those are two lookups, interleaved with parsing the value. And
`relations._blocked` asks the same checker about a document as it would read
after the fixer's edits, which exists only in memory. Record facts cannot
describe that without a solve per file. Rules there would read worse and run
slower, which are two of the ADR's kill criteria. The owner chose to drop
`contract` and port `ref_status` instead, and the ADR's list now says why.

What `ref_status` decides is a join: citation sites, annotations and
document states, matched by file, code, line and kind. The scan still finds
the sites in prose (blanking URLs, directives, `formerly:` entries, chain
fields and composed remote codes). It then hands
`luria/logic/acknowledgements.lp` the sites, the annotations and which codes
resolve and are in force. The program decides:

- **excused/2**: the first well-formed annotation in the file that names the
  code, governs the line and claims the site's state, and failing that the
  first `mention-ok`;
- **unused/1**: a well-formed annotation that answers for nothing;
- **lost/3**: what a malformed annotation left unacknowledged.

This replaces `mention_for`, the three `next(...)` excuse searches,
`Scan.used`'s identity walk over every site, and `_unexcused_under`.

On the anthology the scan finds 15,893 sites and 1,212 annotations. The
solve takes 0.3 s and the whole scan is unchanged: 0.36.0 took 7.4 s and
the candidate 6.9 s.
