Two questions were left open after the logic-core ports.

**The small examples were slower by a fixed amount.** Parity had them
0.1-0.3 s slower in total over five commands. Fifteen alternating runs per
command on `examples/knowledge-base` put the gap at +11 ms (`index`),
+23 ms (`reports`) and +32 ms (`lint`), as medians. The pieces:

- importing clingo, about 8 ms, which every command pays because config load
  checks consistency through it;
- about 1 ms per solve, mostly clingo parsing the rule text, with three at
  config load;
- `rules()` reading each `.lp` file on every call;
- one `git rev-parse` (about 1.5 ms) per read of the facts, to stamp HEAD.

Now rule files are cached, config load shares one answer between its two
scheme passes, and the HEAD stamp is the `HEAD` file plus `stat`s of the ref
it names and of `packed-refs`. git is asked for the git directory once per
root, and asked again if a `.git` appears. Re-measured, the gap is +12 to
+21 ms, within run-to-run noise of about 10 ms. The import is the floor, and
it is the price of the dependency.

**The facts took 17.9 s of wall time inside nucleation's lint.** That
figure predates the race fix; afterwards the facts took 0.28 s pooled
against 0.13 s serially. One phase still swelled: the first relations
solve, at 3.46 s pooled against 0.075 s serially. Taken apart serially, it is
9 ms building program text, 30 ms of clingo parsing, 7 ms grounding, 1 ms
solving and 12 ms converting. With the markers now reporting thread CPU time,
the pooled run says it directly: 3.918 s of wall time, 0.188 s of CPU. The
solve thread waited for the GIL behind the render pool, and the command
total is the same pooled or serial (about 55 s against 53 s). Nothing to fix
in the solve. The markers were what needed fixing, because a wall-time-only
line had invited exactly the misreading this follow-up was opened to check.
