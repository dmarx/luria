---
title: 'Explicit relations: what the migration found, and the remote target it needed'
created: '2026-10-08T04:48:39'
tags: []
---

The request was to make configuration the only source of relation
semantics, so that the facts layer stops omitting relation types and
`relations.lp` stops inferring them from an absence. Three things came out
of doing it that were not in the request.

**Remote successors are real, so references can target remotes.** A scan of
every successor value in the ten records found one LIT in nucleation
superseded by an `ANTH-` code and one LIT in the anthology superseded by an
`ARXIV-` code. The implicit any-scheme reference had allowed these. A
concrete local target set could not, and an explicit `*` would have brought
back the thing being removed. So `scheme:` may now name declared remotes:
`scheme: [LIT, ARXIV]`. `contract.remotes_of` reads them, a remote code
passes where its remote is named, and the graph still draws no edge to a
remote.

**The index needed a role, not a rename.** The "shaped by" line read
`influenced_by` by name. Removing it would change the index pages of luria's
own record and the anthology. Keeping the name keeps the special case. So
`influence:` names the declared reference the index renders, as `successor`
does for retirement, and config load refuses one that names nothing
declared.

**The test helper was leaking.** `merged()` merged dict fragments by
reference, so one test's extra keys mutated a module-level fragment that
the next test reused. It only surfaced when the new tests passed role dicts
through it. It deep-copies now.

The migration reads the old config with its roles stripped in memory,
because an old config may name a `successor` it never declared. It does
this through `config.rooted(root, text=...)`, a new optional argument. It
loads the result before writing anything. On copies of the ten records it
inferred every target set by hand-checkable rule. Parity runs 0.36.0 on
the old record against the candidate on the migrated one, with
`tools/parity.py --upgrade explicit-relations`. One output differs by
design: `docs/record.md`, which now states each scheme's successor
obligation under that scheme instead of as a standard rule.
