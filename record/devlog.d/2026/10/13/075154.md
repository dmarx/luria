[#373](https://github.com/dmarx/luria/issues/373) gives a named pattern a page of its matches ([ADR-tmpgicpu](../../record/decisions.d/ADR-tmpgicpu.md)), as a view
luria supplies on its own template, `luria:pattern.md.j2`.

**The first version was a renderer of its own, and the rework deleted it.**
`pattern_match/2`, a clingo-tuple reader in `logic` and
`pattern_reports.py` duplicated `views._Record.match`, which reached `main`
while the branch was open. As a view, the page's tests from the first
version pass with the same output, link targets included.

- **`match` returned one row per whole match**, so two matches differing
  only in an anonymous node were two identical rows. It now collapses them.
- **No pair of outputs was checked for collisions**; now all are, in one place.
- **YAML eats property maps**: fold (`>-`) or quote a pattern holding one.
- **`luria new changelog --name <branch>` returns an existing path** on a
  reused branch, and a shell redirect overwrites the previous fragment.

On nucleation the unopposed count moved from 115 of 175 theses to 286 of
361 because the record grew; undercut stayed at 8 rows.

**Follow-up:** `pattern_row/4` (views) and `pattern_node/4` (the `report:
true` classes) are two encodings of one match. A test pins that the page and
the class agree; one predicate for both would remove the need.
