`CLAUDE.md` named the generated files by hand, in a bullet saying never to
edit them. The list is now derived in its template, from loops over
`schemes()`, `journals()`, `chains()` and `views()`, plus `paths()` for
the pages luria renders at fixed places. A first version put the list in
`Config.generated()` and had `is_generated` ask it, so the check and the
page would share one list. It was dropped in review: the labels and the
loops are presentation and belong in the template, and `is_generated` was
right as it stood.

The cost is a second derivation of "what luria writes", in the template,
so the guard is a property and not a list ([DP-003](../../record/principles.d/DP-003.md)). Every file
`luria index` renders for this record has to fall under a path the
rendered bootloader names. I fired it once ([DP-006](../../record/principles.d/DP-006.md)): with the journals
loop deleted from the template, it failed and named
`docs/devlog/2026-10.md`. A new kind of generated output fails it until
the template learns to say it.

Trap: `adr_index.outputs()` includes nested records' views ([ADR-078](../../record/decisions.d/ADR-078.md)),
which this record's bootloader does not name. The test asks
`outputs(nested=False)`.
