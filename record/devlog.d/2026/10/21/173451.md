**Why the key is on the cited scheme and names a citer.** nucleation's
`QUESTION` scheme warned at every citation of an `Answered` question. The
citations from the open parent that the answered child was split off are
correct, and the rest are worth the warning. Widening `active` would have
silenced both. `citable_from` ([ADR-tmpfu1s6](../../record/decisions.d/ADR-tmpfu1s6.md)) names the citer by scheme and
status. Anything else, a file outside the record included, is judged as
before.

**Where the citer comes from.** `_scan` already had `own`, the map from a
document's path to its code, for skipping self-citations. `Doc` now carries
its scheme's prefix, so the citer's scheme and status are one lookup. The
decision is a Python test that states `sanctioned(I)`. The logic program
only reads a sanctioned site as not retired, so the acknowledgement rules
did not change.

**The trap: three readers decided "loud" for themselves.** `flagged`, `luria
ack` and the pending report each tested `excused_by is None`. Changing only
one would have left `luria ack` offering to write a directive over a site
that needs none, and that directive is a stale finding as soon as it is
written. `Citation.loud` is now the one test. The export's `excused` column
still means "a directive acknowledges it", as its schema says.

**Fired on a real case ([DP-006](../../record/principles.d/DP-006.md)).** I ran the checkout's `luria lint` on a
copy of nucleation, then added `citable_from: {Answered: [QUESTION:Open]}`
to its `QUESTION` scheme and ran it again. The difference, setting aside
upstream identifier checks that depend on the network:

- 13 more stale directives, one for each of the 13 `Answered` questions,
  each in the open parent that cites it. Each was an `inactive-ok` that
  nucleation had written to silence exactly this warning.
- No retired-citation row appeared or disappeared, so no warning outside
  the declared citer was silenced.

The first firing showed a wording bug. The stale message said "nothing in
scope cites QUESTION-249", which was false, because the parent does cite it.
`stale_annotations` now says the code "is cited here from where its scheme's
`citable_from` allows, so needs no acknowledgement".
`tests/test_citable_from.py` pins that wording, and it pins the
non-sanctioned citers (another status, another scheme, a plain file) and
each config refusal.
