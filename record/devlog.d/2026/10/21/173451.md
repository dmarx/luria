**The first shape was too narrow.** nucleation's `QUESTION` scheme warned
at every citation of an `Answered` question. The citations from the open
parent that the answered child was split off are correct, and the rest are
worth the warning. The first version of this branch added a per-scheme
`citable_from: {Answered: [QUESTION:Open]}`. Review found it hardcoded
status: status words belong to one scheme, so a rule over a claim's `role`
or `warrant` had no spelling, and `PREFIX:Status` was a second notation for
what a pattern node already says. It became `lint.inactive_ok`
([ADR-tmpfu1s6](../../record/decisions.d/ADR-tmpfu1s6.md)): a one-hop pattern over a reserved `cites` edge, plus a
reason.

**Reusing the pattern machinery without forking it.** `patterns.parse` and
`consistency.check_patterns` each gained one optional argument that says
where the pattern was declared, so their refusals name
`lint.inactive_ok[N]` rather than `patterns.X`. The label and property
checks are reused by passing the pattern with its hop removed, because
`cites` is no reference field and the hop checks would refuse it. The
restrictions on a citation (one hop, `cites` alone, fixed length, no
`WHERE NOT`) are checked in `config._inactive_ok`. Matching happens in
Python, in `ref_status._matches`. It reads a property as `pattern_rules`
does, `status` directly and any other field through `field_rows`, and states
`sanctioned(I)` for the logic program as before.

**Two traps.**
- In `check_patterns`, the new argument was first called `key`, which a
  loop variable in the property check shadows. The refusal then named the
  field instead of the rule. A test caught it.
- A pattern with a property map has to be quoted in YAML. Unquoted, the
  `{` starts a flow mapping and the line fails to parse. The config doc's
  example test caught this in the docstring.

**The trap from the first version still holds: three readers decided
"loud" for themselves.** `flagged`, `luria ack` and the pending report each
tested `excused_by is None`. `Citation.loud` is now the one test.

**Fired on a real case ([DP-006](../../record/principles.d/DP-006.md)).** I compared the reference-status report
(`python -m luria.ref_status --all`) on a copy of nucleation with and
without:

```yaml
lint:
  inactive_ok:
  - match: "(:QUESTION {status: 'Open'})-[:cites]->(:QUESTION {status: 'Answered'})"
    reason: a split parent cites the Answered child split off it
```

- 13 more stale directives, one per `Answered` question, each in the open
  parent and each reading "QUESTION-249 is cited here where
  `lint.inactive_ok[0]` allows it".
- The unacknowledged count was unchanged at 480 rows, so no warning outside
  the rule was silenced.
- The acknowledged count fell from 10265 to 10231. Those 34 sites are now
  sanctioned rather than acknowledged.
- The rule sanctioned citations, so no dead-rule row appeared. A dead rule
  is pinned by `tests/test_inactive_ok_rules.py`.

A full `luria lint` on the copy was stalled by throttled arXiv lookups, so
the report above is the whole of what this rule can change.
