**A downstream backlog luria never surfaced.** [Nucleation's forcing-functions decision](https://github.com/dmarx/nucleation/blob/main/record/decisions.d/ADR-057.md#forcing-functions-making-the-backlog-visible-to-the-lint) measured three blind spots behind more than a thousand undecided documents: credence across an edge was no finding (an Active claim resting on a Proposed one), nothing counted what rests on an undecided document, and an `inactive-ok-file` over a Superseded premise silenced the question forever. [ADR-tmpj2f7s](../../record/decisions.d/ADR-tmpj2f7s.md) makes each a lint finding a record turns on by configuration.

**One matcher.** A reported pattern's rows are a fourth shown predicate of the existing lowering, `pattern_node(P, Match, I, X)`, positional so that a match with no named node is still a row. `pattern_edge/3` was not enough: a single-node pattern emits none, and an all-anonymous one emits no `pattern_row/4`. The class list the dials check is now `lint.failable()` and `lint.mutable()`, which add the record's reported patterns to the static `FAILABLE` and `MUTABLE`. The tuples stay, because a dozen tests assert built-in classes against them.

**The YAML in the request did not parse.** `match: (c:CLAIM {status: 'Active'})-[...]` is a plain scalar containing `: `, which YAML refuses ("mapping values are not allowed here"). The first fixture failed on load before any luria code ran. A `match:` with a property map must be quoted, and the configuration reference's example now is.

**Reliance is `held/4` closed in clingo.** `logic/reliance.lp` takes `reliance(F)` facts as program text, so the memo key distinguishes configurations. Reading `held/4` rather than `ref_value` means a dependence stated only by the premise's converse field (`supports`) counts. The test fixture states one edge that way, and the count of 3 depends on it. A cycle does not make a document its own dependent.

**"Retired" for the expiry check is out of force and not undecided.** Luria's own `retired-citations` treats every non-Active target as retired, which would demand a date on every acknowledged citation of a draft. A `Proposed` premise is what `load-bearing` ranks instead, and a test pins that.

**Fired on fixtures ([DP-006](../../record/principles.d/DP-006.md)).** Each new class has a test that fires it on the shape it exists for and checks the row's text, beside a control that changes one thing and sees it go quiet: an `until` added, the field dropped from `reliance`, `reliance` unset, the target Proposed. The dials are fired too: `fail_on` failing on `inverted_premise` and `load-bearing`, `mute`, a `baseline` holding at 1 and then reporting 2 over it, and `fail_on` refusing a pattern the record has not declared `report: true`.
