title: 'Pattern pages as outlines, and the dialectic at fixed depth'

A pattern page now nests its matches as an outline, and patterns that share
an `output` merge into one ([ADR-tmpkfq4c](../../record/decisions.d/ADR-tmpkfq4c.md)). This answers the case PR [#380](https://github.com/dmarx/luria/issues/380) was
written for, a claim, the argument concluding it and the claims undercutting
that argument, without changing chains.

**The step renderer moved before anything else changed.** `chains._link`,
`_annotation` and `_step` became `luria/steps.py`. A chain page captured
from `main` was pinned as a test first, and it passed before and after the
move. The one generalisation is that a facet the document's scheme cannot
hold is skipped. A chain refuses such a facet at load, so for a chain that
check never fires; for a pattern it is what lets `role` show on claims and
not on arguments.

**The tree is a sort, not a walk.** Every prefix of every match goes into
one dict keyed by its codes, and sorting the keys gives preorder: a prefix
sorts before its extensions, and siblings sort by code. Equal code tuples
are the same node, so a short pattern that is a prefix of a longer one adds
nothing twice. That is merging by position, because the key is the
position's code, not the pattern's variable name.

**One view per output.** `_check_rendered` keys by path, and `_RENDERED`
and `views.outputs()` key by output too, so two pattern views on one path
would have been last-wins. The patterns sharing a page now become one
`View`, keyed `patterns.<first>`, whose `where` names all of them. The
collision check needed one change: it names a pattern page by its first
pattern's key (`luria.yaml: patterns.bare: …`), not by the joined `where`.

**Holding a facet is decided in the logic core**, beside the chain's rule:
`pat_facet/2`, `pat_shown/2` (the label of each named node) and
`pattern_facet_unheld/2` in `consistency.lp`. The wording copies the
chain's, with "neither CLAIM nor ARG declares" for two schemes.

**Nucleation** (scratch copy, `lint.network: never`): without a pattern
`output`, index and lint output are identical to `main`. With the
bare/undercut pair the outline has 9 conclusions, 11 argument nodes over 10
ARGs (ARG-001 concludes CLAIM-057 and CLAIM-086, so it is drawn under both)
and 9 undercutters. An independent script over the frontmatter, reading
`undercuts` and `undercut_by` from both sides, found the same 11 pairs and 9
triples. The four ARGs nothing undercuts are on the page with nothing under
them. The only new lint finding was the docs-index entry for the page.

**Traps.** A template's error line moves whenever the template does. The
render-error test now covers both layouts with their own lines (33 and 13).
In the example, a bare code in the README needs `luria link --fix` run
under `LURIA_ROOT=examples/argument-map`. Run from the repository root, it
reads the root's schemes and leaves `OBJ-001` alone.
