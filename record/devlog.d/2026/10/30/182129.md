title: "A heading's code is checked and concretize writes it"
created: '2026-10-30T18:21:29'

---

**Nucleation's NOTE-1341 came through concretization with a temporary code in its heading.** After the rename it read `# NOTE-tmplu4ga: Guerreiro et al. — xCOMET`, the only such file in that record, and Nucleation fixed it by hand in its commit 230bd4d4b. The note's own temporary code was `NOTE-tmpoaymu`, which its `formerly:` still records. `tmplu4ga` was the tail of the LIT filed on the same branch for the same paper, and the author typed it under the NOTE prefix. So the heading never named its own document. Concretize rewrites every occurrence of the *document's own* temporary code, and `NOTE-tmplu4ga` named no document, so nothing rewrote it. The lint did not catch it either: `check_title` strips the `# CODE:` prefix off the heading and compares only the words after it.

**The fix has two halves, sharing one reader (DP-004).** `luria/headings.py` reads the code a heading carries: the scheme's own prefix is tried first, so a hyphenated prefix is read whole, and the generic shape the index already uses comes second. A number is compared as a number, so `ADR-13` on `ADR-013.md` counts as its own code. `luria lint` now reports a heading whose code is not the document's own, naming both codes and the line to write. That is always wrong and mechanically fixable, so it is an error, not a report. Temporary documents are checked too, so the NOTE-1341 slip fails on its branch while the author still has the context. Concretize also writes the code it assigns into the heading, and prints a line when the heading had carried something other than the old temporary code (DP-001). A heading with no code slot, `# Title`, is left alone.

**The repair was left out.** `luria repair` writes no headings today, not even for a title mismatch, which needs judgement about which copy is right. The code half does not need judgement, because the filename settles it, so a repair could be added later. This change keeps the lint error and its stated remedy. That is a choice of scope, not a rejected alternative.

**Fired on the real case (DP-006).** At Nucleation's tree before the hand fix, main's lint found no heading errors. This branch found nine: NOTE-1341 (`NOTE-tmplu4ga`), and eight more NOTEs, NOTE-1252, NOTE-1254, NOTE-1263, NOTE-1264, NOTE-1265, NOTE-1296, NOTE-1310 and NOTE-1320, whose headings say `NOTE-xxxx`. That is a placeholder typed in their authoring commits and never filled in, and three LITs cite `NOTE-xxxx` in their prose the same way. All nine are real, and the eight are still in Nucleation's current tree. Concretize was also run on Nucleation's tree just before its concretize commit. Main's concretize left `# NOTE-tmplu4ga:`; this branch wrote `# NOTE-1341:` and printed the correction. Its source output differed from main's in that one file only. Luria's own record had four of the same defect: ADR-053, ADR-082, ADR-083 and ADR-086 still carried the template's `ADR-NNN` and are corrected here. strata-g and perspectivelab have none.
