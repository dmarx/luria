**The bug.** [ADR-084](../../record/decisions.d/ADR-084.md) decides a one-sided pair by what changed since HEAD. The working tree side of that comparison, `ref_value`, reads each code through `contract.reference_code`, so a derived alias resolves to the code it names. The HEAD side, `head_value` from `facts.head_facts`, kept the text as written. In `logic/converse.lp`, `was_f` and `was_b` require `doc(X, T)`, so an edge HEAD spelled by alias never counted as present at HEAD. Withdrawing it therefore read as untouched, and the "nothing changed" row writes the missing side back. The fixer re-added the edge the author had just deleted, even before the deletion was committed.

**The fix.** `head_facts` now maps each HEAD value through the current record's derived aliases (`alias_map(cfg)`, `aka` kind only, the same set `derived_code` answers from). A `formerly:` spelling is left as written, as it is for `ref_value`. Resolving against the current record and not HEAD's is deliberate: the baseline is compared to the resolved working tree, so both sides must name codes the same way. Test: `test_a_withdrawn_alias_spelled_edge_prunes_its_converse` in `tests/test_reference_aliases.py`. It failed on main ("the withdrawn edge was written back") and passes with the fix.

**Fired on Nucleation ([DP-6](../../record/principles.d/DP-006.md)).** The case is Nucleation at 181e0cacd^, before status review 23 cluster R2, in a scratch copy committed as its own repository. There, `CLAIM-448` had `grounds: LIT-Jia-2015-1146` and `LIT-1146` had `supports: CLAIM-448`. The review called the alias "a code that names no document"; it names `LIT-1146` through LIT's `alias: LIT-{first_author}-{published:.4}-{number:03d}`. I deleted the ground without committing and listed what the fixer would do. Before the fix: `record/claims.d/CLAIM-448.md add grounds: LIT-1146`, so the deleted ground came back. After: `record/literature.d/LIT-1146.md remove supports: CLAIM-448`. The control, with the same tree but HEAD spelling the ground `LIT-1146`, gave the removal both before and after. The untouched tree reads the same either way: 808 back-references to add, none to remove. This is why the review had to remove that converse by hand.

**What this does not fix.** A withdrawal that is already committed when the fixer runs still reads as "nothing changed" and is written back. That is [ADR-084](../../record/decisions.d/ADR-084.md)'s stated sharp edge, and it is part of the open question of which side of a pair is authoritative. It is not addressed here.
