---
title: 'A formerly list that names its own document: a lint check, fired on 56 real cases'
created: '2026-11-23T01:00:08'
tags: []
---

**The check (check_formerly in lint.py).** A document's `formerly:` list
holds the addresses it used to have. If it names the document's own code,
the list is wrong and the old address is gone.

**How it happens.** In dmarx/nucleation a lead's branch was cut before a
promotion concretized codes it cited. Merging staging back in, the
worker rewrote every temporary code to its concrete one across the
branch. The rewrite also reached the `formerly:` block, where the
temporary code is exactly what should survive. Both parents of that merge
held correct lists, and the result held self-references. Earlier merges
had done the same. Nothing flagged it: the entries parsed, aliases
resolved, and the only sign was a missing temporary code, which no check
looks for. The owner noticed by eye.

**Fired before trusting (DP-006).** Run with `check_frontmatter` against
nucleation's staging as it stood before the repair, it reported 56
documents, the full set the repair found by hand. Against the repaired
branch (dmarx/nucleation, pull request 757) it reported none. It runs in
`check_frontmatter`, so temporary documents meet it too.

**Why a violation and not a report.** It is always wrong, and the
mechanical fix is to delete the line. Restoring the lost code takes
history, and the message says so. The mechanical fix is not applied
automatically: deleting the line would hide the loss that the
self-reference is evidence of.
