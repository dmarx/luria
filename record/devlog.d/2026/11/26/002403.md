---
title: 'A scratch HOME hides user site-packages from a subprocess test'
created: '2026-11-26T00:24:03'
tags: []
---

`tests/test_encoding.py` runs `luria init`, `index` and `lint` in a subprocess
under an ASCII locale, with `HOME` set to the test's tmp_path so nothing
leaks in. In an environment where luria's dependencies were installed into
the user site-packages (root's `~/.local` here), that scratch `HOME` hides
them: the subprocess died on `import jinja2`, and both behavioural tests
reported "init crashed under an ASCII locale" — an import error dressed as
the encoding failure the tests exist to catch. CI's runner installs into the
system site-packages, so it never showed there.

Fix: one `ascii_env()` helper for both tests, passing the parent's
`sys.path` as `PYTHONPATH`. The import path has nothing to do with the
encoding under test.

Fired before trusting ([DP-006](../../record/principles.d/DP-006.md)): with `writes.py` switched to
`encoding="ascii"`, the behavioural test fails on `UnicodeEncodeError … '—'`
— the real failure — and passes again once restored.

The trap generalizes: any subprocess test that scrubs `HOME` for isolation
also scrubs the user site. Pass the import path explicitly.
